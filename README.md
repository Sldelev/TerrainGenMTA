# TerrainGen

Клиентский ресурс процедурной местности для MTA. Местность генерируется на клиенте из шума Перлина, с одинаковым SEED у всех игроков, поэтому ландшафт совпадает у всех без передачи данных по сети. Вокруг игрока чанки строятся, освещаются, отрисовываются с LOD и получают коллизию в виде COL-файлов.

## Структура

```
TerrainGen/
├── meta.xml   порядок загрузки скриптов и файлов
├── config.lua        все константы и общее состояние (ColGen.cfg, ColGen.state)
├── noise.lua         перестановка по SEED, perlin2, smoothstep
├── lighting.lua      время суток, затенение граней, refreshLight
├── terrain.lua       heightAt, веса слоёв, геометрия чанка с кэшем
├── mesh.lua   вершины для LOD 1 и LOD 2, юбки
├── col.lua    запись COL3, attachCollision / detachCollision
├── streaming.lua     подгрузка и выгрузка чанков, updateChunks
├── render.lua        шейдер и текстуры, отрисовка, отбраковка, /colgrid
├── client.lua        обработчики событий и замер рендера
├── reference.col     эталон COL3 (для сверки формата)
└── Assets/
    ├── Textures/     Grass.png, sand.png, rock.png, snow.png
    └── Shaders/      terrain.fx
```

Модули общаются через глобальную таблицу `ColGen`. `config.lua` загружается первым и создаёт `ColGen.cfg` и `ColGen.state`. Остальные файлы добавляют в неё функции. Порядок в `meta.xml` важен: каждый модуль использует то, что загружено раньше.

## Высота рельефа

Функция `heightAt(x, y)` в `terrain.lua` возвращает высоту точки над `BASE_Z` (500) и маску оврага. Она складывает несколько слоёв:

1. **Доменное искажение.** Координаты сдвигаются двумя шумами (`WARP_AMOUNT`, `WARP_SCALE`). Благодаря этому формы не повторяются регулярно, а контуры выглядят естественнее.
2. **Базовый рельеф.** Многооктавный шум (`BASE_OCTAVES`, `BASE_SCALE`, `BASE_HEIGHT`) даёт плавные неровности.
3. **Холмы.** Ещё один слой с большим масштабом (`HILL_SCALE`, `HILL_HEIGHT`).
4. **Горы.** Маска низкой частоты (`MOUNTAIN_MASK_SCALE`) решает, где есть горы, через `smoothstep`. Внутри маски высоту задаёт гребневой шум `ridged` (`RIDGE_OCTAVES`, `RIDGE_SCALE`): он даёт острые хребты. Высота гор ограничена `MOUNTAIN_HEIGHT`.
5. **Овраги.** Модуль шума по `|perlin2|` даёт узкие полосы. Маска оврага `ravineMask` вычитает до `RAVINE_DEPTH` из высоты и отдаётся вызывающему коду для выбора материала.

Все шумы детерминированы: перестановка строится из `SEED` через генератор LCG, поэтому результат одинаков на всех клиентах.

## Материалы

`layerWeights(z, ravine)` возвращает три веса: камень (по высоте выше `STONE_HEIGHT`), снег (выше `SNOW_HEIGHT`) и песок (внутри оврага, по `SAND_RAVINE`). Переходы сглажены через `smoothstep` с шириной `BLEND_*`. Если сумма весов больше 1, они нормируются. Остаток идёт на траву.

Веса пишутся в цвет вершины (`COLOR0`): r — камень, g — снег, b — песок. Затенение граней пишется в альфа-канал. Смешивание делает шейдер (см. ниже), поэтому переходы не используют альфу и не дают артефактов на границах.

## Геометрия чанка

- Клетка `CELL` = 8 м, чанк = `CHUNK_CELLS` клеток = 32 м.
- Чанк `(cx, cy)` занимает область от `cx * 32` до `(cx + 1) * 32` по X и Y.
- Сетка чанка 5×5 точек. Каждая точка хранит координаты, высоту и маску оврага.
- `getGeometry(cx, cy)` строит сетку один раз и кладёт её в кэш с лимитом `(2 * CACHE_RADIUS + 1)²` записей. Самый старый элемент вытесняется.

## Стриминг

`updateChunks` (`streaming.lua`) запускается таймером каждые `STREAM_INTERVAL` мс:

1. Обновляется освещение (`refreshLight`).
2. Вычисляется чанк игрока. Если его нет, создаётся визуальная часть.
3. Вокруг игрока до радиуса `CACHE_RADIUS` создаются визуальные чанки, не больше `VISUAL_PER_TICK` за тик. Визуальная часть — это только вершины, без коллизии.
4. Чанки дальше `CACHE_RADIUS` удаляются полностью, а чанки дальше 1 теряют коллизию.
5. Коллизия грузится не больше `COLLISION_PER_TICK` за тик, только для центрального чанка и его восьми соседей (`COLLISION_OFFSETS`).

Такое разделение нужно потому, что `engineLoadCOL` — самая дорогая операция (около 10–13 мс на чанк). Визуал дешёвый, поэтому дальние чанки видны, но не сталкиваются.

## Коллизия

`col.lua` собирает бинарный COL3-файл из вершин и граней чанка:

- заголовок `terrain` + ID модели, границы (min, max, center, radius) в float32;
- вершины как int16 с масштабом 128;
- грани как три uint16 и два байта-пустышки;
- смещения считаются относительно `OFFSET_BASE`.

Файл пишется во временный `chunk_cx_cy.col`, загружается через `engineLoadCOL`, подменяет модель через `engineReplaceCOL` и сразу удаляется. Для чанка создаётся невидимый замороженный объект (`createObject`, `setElementAlpha(0)`) в центре чанка на высоте `BASE_Z`. При выгрузке коллизия возвращается через `engineRestoreCOL`, модель освобождается через `engineFreeModel`.

## Освещение

`faceShade` вычисляет нормаль грани векторным произведением и берёт скалярное произведение с направлением солнца `SUN`. Результат — яркость 0..255 с учётом `AMBIENT`, `DIFFUSE_STRENGTH` и текущего `light`.

`getTimeLight` задаёт множитель по часам: день 1, ночь `NIGHT_LIGHT`, плавные переходы в 5–7 и 19–21. Когда освещение меняется заметно (`LIGHT_EPSILON`), у всех чанков сбрасывается кэш отрисовки, и вершины пересчитываются с новым светом.

## LOD

- **LOD 1** (`buildVertices`): полная сетка 4×4 клетки, для чанков в радиусе `LOD_NEAR_RADIUS` от игрока.
- **LOD 2** (`buildFarVertices`): сетка с шагом `LOD_FAR_STEP` клеток, то есть 2×2 квадрата на чанк. Вершины пересчитываются из шума, потому что их нет в кэше.
- Для LOD 2 строятся **юбки** (`SKIRT_DEPTH`): по периметру чанка вершины уходят вниз, чтобы закрыть стыки между чанками разного LOD.

Результат каждого LOD кэшируется в `chunk.draw[lod]` и сбрасывается при смене освещения.

## Отрисовка

`renderChunks` (`render.lua`) выполняется в `onClientRender`:

1. Берётся камера (`getCameraMatrix`) и направление взгляда.
2. `isChunkVisible` отбраковывает чанки. Чанк внутри радиуса `CULL_RADIUS` всегда виден. Дальше проверяется угол относительно взгляда и `CULL_HALF_ANGLE`.
3. Для каждого видимого чанка выбирается LOD и вызывается `dxDrawMaterialPrimitive3D` с шейдером `terrain.fx`.

Шейдер `Assets/Shaders/terrain.fx`:
- вершинная часть передаёт веса материалов и затенение из `COLOR0`;
- пиксельная часть берёт четыре текстуры с `Wrap`-адресацией, масштаб `TILE` = 8 м;
- цвет получается как сумма травы, камня, снега и песка с весами, затем умножается на затенение.

## Отладка

- `/colgrid` включает и выключает отрисовку сетки чанков.
- В лог через `outputDebugString` пишутся средние значения: `colgen collision avg` (время загрузки COL за 20 чанков) и `colgen render avg` (время отрисовки за 300 кадров).
- Если шейдер не компилируется, в лог выводится `TerrainGen: terrain.fx failed to compile`.

## Известные ограничения

- Коллизия грузится с задержкой: при быстром движении на краях зоны возможны кратковременные провалы.
- `engineLoadCOL` остаётся основным узким местом. Время загрузки зависит от размера чанка и не сильно меняется от оптимизаций в Lua.
- Параметры рельефа (`config.lua`) подобраны по ощущениям.
