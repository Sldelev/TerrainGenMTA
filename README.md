# TerrainGen

Клиентский ресурс процедурной местности для MTA. Местность генерируется на клиенте из шума Перлина с одинаковым `SEED` у всех игроков, поэтому ландшафт совпадает без передачи данных по сети. Вокруг игрока чанки строятся, освещаются, отрисовываются с LOD и получают коллизию в виде COL-файлов.

Чанк занимает `CHUNK_SIZE` = 128 м (16×16 клеток по `CELL` = 8 м). Все числа ниже берутся из `config.lua`, при изменении конфига этот файл может отстать.

## Структура

```
TerrainGen/
├── meta.xml          порядок загрузки скриптов и файлов
├── config.lua        все константы и общее состояние (ColGen.cfg, ColGen.state)
├── noise.lua         перестановка по SEED, perlin2, smoothstep, планировщик корутин
├── debug.lua         статистика и панель /tgdebug
├── lighting.lua      время суток, затенение граней, refreshLight
├── roads.lua         трасса дороги, ветки, врезка в рельеф, полоса и откосы
├── terrain.lua       heightAt, веса слоёв, геометрия чанка с кэшем
├── mesh.lua          вершины для LOD, юбки, выбор LOD
├── dff.lua           запись DFF для визуала и дорог
├── col.lua           запись COL3, attachCollision / detachCollision
├── streaming.lua     подгрузка и выгрузка чанков, updateChunks
├── render.lua        шейдер и текстуры, отрисовка, отбраковка, /colgrid
├── client.lua        обработчики событий и команды
└── Assets/
    ├── Textures/     текстуры рельефа и дороги (пути в config.lua)
    └── Shaders/      terrain.fx, road.fx
```

Модули общаются через глобальную таблицу `ColGen`. `config.lua` загружается первым и создаёт `ColGen.cfg` и `ColGen.state`. Остальные файлы добавляют в неё функции. Порядок в `meta.xml` важен: каждый модуль использует то, что загружено раньше.

## Высота рельефа

`heightAt(x, y)` в `terrain.lua` строит высоту через `rawHeightAt` и затем применяет дороги (`applyRoad`). Основные параметры лежат в `config.lua`:

- **Смещение координат.** `WARP_AMOUNT` (70) сдвигает точку шумом, чтобы формы не повторялись регулярно.
- **Базовый рельеф.** Многооктавный шум `fbm` с `BASE_HEIGHT` (10) даёт плавные неровности.
- **Холмы.** `HILL_HEIGHT` (35) задаёт верхнюю амплитуду холмов.
- **Овраги.** Маска оврага строится из `fbm` с порогами `RAVINE_MASK_LOW` и `RAVINE_MASK_HIGH`. Глубина вычитается до `RAVINE_DEPTH` (14). Маска передаётся дальше для выбора материала.

Шум детерминирован: перестановка строится из `SEED` (1337) через LCG, поэтому у всех клиентов одинаковая высота.

## Дороги

`roads.lua` строит трассу, которая выбирается по рельефу и выглядит одинаково у всех игроков.

- Трасса проходит по узлам с шагом `ROAD_NODE` (16 м) вдоль X. В каждом узле дорога может смещаться поперёк на `ROAD_LATERAL` (8 м) в пределах `±ROAD_LATERAL_RANGE` (12 м).
- Выбор маршрута идёт блоками по `ROAD_BLOCK_NODES` (16) узлов динамическим программированием. Стоимость сегмента (`stepCost`) учитывает длину и уклон, который ограничивает `ROAD_MAX_GRADE` (0.2).
- Полотно выравнивается к рельефу в полосе `ROAD_HALF_WIDTH` (4 м). Переход к рельефу идёт в зоне `ROAD_SHOULDER` (16 м). Это делает `applyRoad`.
- Ответвления строит `buildBranch`. Появляются с вероятностью `ROAD_BRANCH_CHANCE` (0.35), полилиния прореживается с допуском `ROAD_DECIMATE_TOL` (0.8).
- Откосы строятся треугольниками по обе стороны полотна. Внешний край ограничен `ROAD_SLOPE_GRADE` (1/3) и не дальше `ROAD_SLOPE_MAX` (8 м).
- Полоса рисуется отдельным мешем (`getRoadDraw`) шейдером `road.fx`. Гравий смешивается по `ROAD_GRAVEL_LOW` (0.15) и `ROAD_GRAVEL_HIGH` (0.35).
- Треугольники дороги выдаются по чанкам (`getRoadTriangles`), поэтому полоса и откосы не обрываются на границе чанка.
- В коллизию попадают полотно и откосы при `ROAD_SIDE_COLLISION` = true (`withRoads` в `col.lua`).
- Блоки трассы, ветки и треугольники кэшируются. Лимит каждого кэша — `ROAD_CACHE_LIMIT` (5000).

## Материалы

`layerWeights(z, ravine)` в `terrain.lua` возвращает вес песка внутри оврага (по `SAND_RAVINE` и `BLEND_RAVINE`) и нули для камня и снега. Остаток идёт на траву. Камня и снега на холмах сейчас нет.

Веса пишутся в цвет вершины (`COLOR0`): r — камень (всегда 0), g — снег (всегда 0), b — песок. Затенение граней пишется в альфа-канал. Смешивание делает шейдер `terrain.fx`, поэтому переходы не используют альфу.

## Геометрия чанка

- Клетка `CELL` = 8 м, чанк = `CHUNK_SIZE` = 128 м, то есть `CHUNK_CELLS` = 16 клеток на сторону.
- Чанк `(cx, cy)` занимает область от `cx * 128` до `(cx + 1) * 128` по X и Y.
- Сетка точек чанка — 17×17 (`CHUNK_CELLS + 1`). Каждая точка хранит координаты, высоту и маску оврага.
- `getGeometry(cx, cy)` строит сетку один раз и кладёт в кэш с лимитом `GEOMETRY_CACHE_LIMIT`. Самый старый элемент вытесняется. Построение разбито на строки, между строками стоит `yieldIfOver`.

## Стриминг

`updateChunks` (`streaming.lua`) запускается таймером каждые `STREAM_INTERVAL` мс (100 мс):

1. Обновляется освещение (`refreshLight`), вычисляется чанк игрока.
2. Чанк игрока строится как приоритетная задача (`spawnKeyed("center", ..., true)`): сначала визуал, затем коллизия. Задача встаёт в начало очереди, поэтому выполняется раньше остальных.
3. Кольца вокруг игрока до радиуса `CACHE_RADIUS` (от 1 до 8 чанков, по умолчанию 3) проверяются функцией `scanRings`. Если у чанка нет дорожных треугольников, визуала или нужного LOD, создаётся задача для этого чанка. Задача с тем же ключом не создаётся повторно, пока первая не закончилась.
4. Чанки дальше `CACHE_RADIUS` удаляются полностью, чанки дальше 1 теряют коллизию.
5. Коллизия грузится для центрального чанка и его восьми соседей (`COLLISION_OFFSETS`), каждая задача с ключом `col:<x>:<y>`.

### Планировщик

Тяжёлая работа выполняется корутинами (`noise.lua`). `ColGen.pump()` вызывается в `onClientRender` перед отрисовкой и выполняет задачи, пока с начала кадра прошло меньше `TICK_BUDGET_MS` (2 мс). Внутри длинных циклов стоит `ColGen.yieldIfOver()`: он отдаёт управление, если бюджет кадра исчерпан. Вне корутины вызов ничего не делает. Точки уступки есть в `solveBlock`, `buildBranch`, `getRoadTriangles`, `buildChunk`, в DFF- и COL-сборке.

Синхронные вызовы, например `getRoadDraw` при отрисовке, точек уступки не используют.

### Визуал и коллизия

Визуал (вершины и LOD) строится дешевле коллизии, поэтому коллизия грузится только для центрального чанка и его соседей. Дальние чанки видны, но не сталкиваются.

LOD выбирается по расстоянию в чанках из `LOD_LEVELS` (`lodForDistance` в `render.lua`, `streaming.lua`). `flatLod` в `mesh.lua` может выбрать более грубый уровень для плоского чанка. Результаты DFF кэшируются на диске с именами `r_v<версия>_...` для дорог и `t_v<версия>_...` для рельефа. Версия задаётся `CACHE_VERSION` (8), при изменении формата её нужно поднять.

## Коллизия

`col.lua` собирает COL3 из вершин и граней чанка (функция `buildCol`):

- границы (min, max, center, radius) считаются в `computeBounds` и пишутся в заголовок;
- координаты вершин пишутся как int16, умноженные на 128 (`i16(round(v * 128))`);
- смещения секций считаются относительно `OFFSET_BASE` (4);
- при сборке совпадающие вершины объединяются по ключу с точностью 1/128 (`withRoads`).

Готовый файл загружается через `engineLoadCOL` и подменяет модель через `engineReplaceCOL`. При выгрузке используется `engineRestoreCOL`, а модель освобождается через `engineFreeModel`. Пул моделей ограничен `COL_POOL_LIMIT` (24), лишние модели вытесняются (`evictFromPool`).

## Освещение

`faceShade(p1, p2, p3, light)` в `lighting.lua` считает яркость грани: нормаль берётся из трёх точек и сравнивается с направлением солнца. Итог складывается из `AMBIENT` (0.45) и `DIFFUSE_STRENGTH` (0.55) и умножается на текущий `light`.

`getTimeLight` задаёт `light` по времени суток, ночью он опускается до `NIGHT_LIGHT` (0.2). `refreshLight` вызывается из `updateChunks` и обновляет освещение только когда изменение больше `LIGHT_EPSILON` (0.02).

## LOD

`LOD_LEVELS` в `config.lua`:

- **LOD 1**: радиус 1 чанк, шаг 1 клетка (8 м). Строится через `buildVertices`.
- **LOD 2**: радиус 3 чанка, шаг 2 клетки (16 м). Строится через `buildFarVertices`.
- **LOD 3**: без ограничения радиуса, шаг 4 клетки (32 м). Строится через `buildFarVertices`.

Для грубых уровней строятся **юбки** (`emitSkirt`, `SKIRT_DEPTH` = 12 м): края опускаются вниз, чтобы закрыть щели между чанками разных уровней. Вершины LOD получает `getChunkDraw(chunk, lod)`.

## Отрисовка

`renderChunks` (`render.lua`) выполняется в `onClientRender` после `pump`:

1. Берётся камера (`getCameraMatrix`) и направление взгляда.
2. `isChunkVisible` отбраковывает чанки. Чанк внутри `CULL_RADIUS` (140 м) всегда виден. Дальше проверяется угол относительно взгляда и `CULL_HALF_ANGLE` (75°).
3. Для каждого видимого чанка выбирается LOD и вызывается `dxDrawMaterialPrimitive3D` с шейдером `terrain.fx`.

Шейдер `terrain.fx`:
- четыре текстуры материалов с `AddressU/V = Wrap`, фильтры `Linear` для минификации, увеличения и мипов;
- текстуры создаются в `render.lua` с мип-картами (`dxCreateTexture(..., "argb", true)`);
- масштаб текстур задаёт `TEXTURE_TILE` (8) в `config.lua`.

Дорожная полоса рисуется `road.fx`. Шейдер получает текстуры дороги, песка, травы и гравия (`gRoad`, `gSand`, `gGrass`, `gGravel`). Гравий повторяется с масштабом `ROAD_GRAVEL_TILE` (6).

## Команды

- `/tgrender`, `/tglod`, `/tgdff` — отладочные команды из `client.lua`.
- `/tgstat` — выводит `CACHE_RADIUS`, число чанков, сколько из них с объектом, и максимальный радиус.
- `/colgrid` — включает и выключает сетку чанков.
- `/TerrainGen drawDistance <метры>` — задаёт дальность. Дистанция ограничена `DRAW_DIST_MAX` (512 м), радиус кэша чанков — `CACHE_RADIUS_MIN`..`CACHE_RADIUS_MAX` (1..8).
- `/tgdebug` — панель статистики из `debug.lua`. `/tgdebug reset` сбрасывает статистику.

## Известные ограничения

- Синхронные вызовы вроде `getRoadDraw` не уступают кадр, поэтому при первом построении дороги возможен заметный разовый лаг.
- Ожидающие ключи задач не очищаются при вытеснении чанка из кэша.
